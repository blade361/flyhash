Search that works the way a fly smells

A fruit fly identifies an odour with about 2,000 neurons and no training data. The same trick gives you fuzzy record matching in 256 bytes per row, with no embedding API and no vector database.

Against a contact list

Sixteen records, deliberately messy: abbreviations, misspellings, German and Spanish, the kind of thing that accumulates in a CRM. Every one was hashed once. Searching is counting.

What it is doing

  1. Turn the text into 4,096 numbers by counting words and character fragments.
  2. Scatter those onto 2,048 cells through fixed random connections, each cell sampling six inputs. The data gets bigger, which is the point.
  3. Keep the loudest 5%, switch everything else off. That's the tag.

Nothing is learned. The connections are generated once from a seed and never change, which is exactly what the fly does. It means no training step, no model to host, and a tag that stays valid for as long as the seed does.

What it is not doing

It has no idea what words mean. "Skip hire" and "waste disposal" share no characters, so they score at the noise floor. This is a fast first pass over shared vocabulary, spelling and typos, not a semantic search. Use it to narrow thousands of rows to fifty, then send those fifty to a model if you need meaning.

Method from Dasgupta, Stevens & Navlakha, A neural algorithm for a fundamental computing problem, Science 2017. This page runs the real implementation, not a mock-up.
